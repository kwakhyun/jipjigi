# 제출 포트폴리오와 현재 버전의 정합성

2026-09-05에 제출본 PDF 5페이지의 본문, 화면과 링크를 현재 저장소 및 개선 후 검증 결과와 대조했다. 제출본은 변경하거나 다시 생성하지 않았다. 기술 구성이나 핵심 체험을 바꾸는 모순은 발견하지 않았으며, 화면과 검증 수치의 차이는 기준일이 다른 개선 이력으로 구분한다.

## 페이지별 확인

| --- | --- | --- |

## 검증 수치의 기준일

PDF 5쪽에는 “검증 수치는 2026년 8월 31일 기준입니다”라고 명시되어 있다. 따라서 이후 회귀 테스트 추가나 번들 크기의 변화는 과거 검증 결과와 모순되지 않는다.

| 항목 | 제출본, 2026-08-31 | 개선 후 로컬 검증, 2026-09-05 |
| --- | --- | --- |
| 웹 테스트 | 31개 파일, 126개 | 33개 파일, 138개 |
| 공통 패키지 테스트 | 8개 | 8개 |
| 실제 웹앱 E2E | 4개 | 7개. 기존 여정에 모바일 개선과 실제 색 대비, 200% CSS 확대 검사 추가 |
| 타입과 빌드 | 5개 패키지와 프로덕션 빌드 통과 | 동일 범위 통과 |
| 홈 gzip / 예산 | 177.3 / 185KiB | 177.3 / 185KiB |
| 메시지 gzip / 예산 | 168.0 / 170KiB | 168.7 / 170KiB. 기존 예산 유지 |
| 접근성 | 주요 흐름에 axe 적용 | 기존 컴포넌트 검사에 6개 화면 × 2개 너비의 실제 브라우저 색 대비 검사 추가 |

원래 화면의 ‘나머지 15세대’는 초기 데모의 입주 18세대 중 서로 다른 3세대에 문제가 있는 상황과 맞는다. 여러 문제가 같은 종류나 같은 세대에 발생할 때의 일반화된 집계 오류를 이번에 수정했으며, 당시 캡처를 수정 후 UI처럼 교체하지 않는다. 해당 화면 원본은 `.design-qa/portfolio-readiness`에 보존되어 있다.

## 링크와 제출본 보존

PDF에서 `github.com/kwakhyun/jipjigi/blob/main/`으로 연결하는 고유 파일 경로 11개가 모두 현재 저장소에 존재한다. DAL 분리 후에도 PDF가 직접 참조한 실험 코드, 가드레일, CRM 통합 테스트와 문서 경로는 유지된다. 이 확인은 저장소 경로의 연속성을 뜻하며, 외부 서비스의 상시 가용성을 보장하는 검사는 아니다.

제출본 확인용 SHA-256:

```text
4eeda93c0368356abda355025fb44cf5afeff90538a2f0b849ae2325e76b5677
```

PDF와 작성 원본은 기존 `.gitignore` 정책에 따라 로컬에 보존한다. 저장소에는 이후 개선 코드, 문서와 검증 근거를 공개한다. 이번에 구현한 동시성 보강이나 실제 색 대비 검사가 제출일에도 완료되어 있었다고 소급해서 설명하지 않는다.

개선 결과는 [문제별 수정 기록](audits/2026-09-05-remediation.md), 명령 출력은 [검증 근거](audits/2026-09-05-remediation-evidence/), 현재 배포 및 CI 상태는 해당 커밋의 검사 결과로 확인한다. 로컬 통과 결과만으로 원격 CI나 운영 배포까지 완료되었다고 해석하지 않는다.
