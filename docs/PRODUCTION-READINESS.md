# 프로덕션 준비 상태

## 현재 실행 가능한 범위

현재 저장소는 인증된 임대 운영 웹앱의 완결된 세로 단면을 제공합니다. 로그인한 사용자는 건물 브리핑을 보고, 계약 갱신 확인과 미납 안내를 접수하고, 수리 상태와 납부 상태를 변경할 수 있습니다. 각 변경은 Neon Postgres에 저장되고 감사 로그와 제품 이벤트로 이어집니다. 로컬 개발과 테스트는 같은 PostgreSQL 문법을 사용하는 PGlite로 재현합니다.

구현된 운영 경계는 다음과 같습니다.

- 서명된 HTTP 전용 세션 쿠키와 요청별 사용자 재검증
- 건물 소유권을 포함한 모든 변경 대상 재조회
- 임차인 연락 동의, 7일 빈도 제한, 조용한 시간대 예약
- 갱신 24시간 제한, 청구월 단위 미납 멱등 처리와 최근 7일 2회 상한
- 전달 실패 재접수, 계약 단위 응답 타임라인과 HMAC 웹훅 검증
- 허용 목록 기반 제품 이벤트 속성 필터링
- 사용자 ID 기반 고정 A/B 배정과 실제 노출 기록 분리
- 지역 랜딩 정적 생성, 메타데이터, 구조화 데이터, 사이트맵
- 상태 확인 API, 구조화 로그, 독립 오류와 로딩 화면
- Core Web Vitals 수집, 최근 7일 p75 관제, CI 전송량 예산
- CRM 전달률, 7일 수신 해제율과 발송 차단률 관제
- Upstash Redis sliding window와 운영 환경 장애 시 차단 우선 처리
- Vercel 운영 환경에서 Neon 또는 Upstash가 빠지면 503을 반환하는 상태 확인

## 외부 계약 전에는 켜지 않는 기능

아래 기능은 공급자 계약이나 운영 자격 증명이 없으므로 실제 연동이라고 주장하지 않습니다.

- 카카오 알림톡 실제 발송
- 은행 입금 내역 자동 수집
- 본인인증, 결제, 임대차 신고
- 광고 네트워크와 앱 푸시 공급자

현재 `sandbox_alimtalk` 어댑터가 동일한 메시지 상태 모델을 사용합니다. 실제 공급자는 어댑터를 교체하고 비밀 키를 주입한 뒤 계약 테스트를 통과해야 합니다.

## 트래픽 확장 전에 보강할 부분

공유 영속 저장소와 분산 요청 제한은 구현했습니다. 실제 사용자 트래픽을 받기 전에는 다음 운영 기능을 보강해야 합니다.

1. SQL 스키마 변경을 독립된 버전 관리형 마이그레이션 작업으로 분리합니다.
2. 제품 이벤트와 RUM을 내구성 큐로 보내고 웨어하우스 적재 실패를 재시도합니다.
3. 실제 인증 공급자, 사용자 초대, 비밀번호 재설정과 MFA를 연결합니다.
4. 중앙 비밀 값 관리, 로그 수집과 오류 추적을 운영 환경에 연결합니다.

운영 환경은 `DATABASE_URL`과 Redis REST 인증 정보가 있어야 정상으로 판정됩니다. Redis는 `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` 또는 Vercel Marketplace의 `KV_REST_API_URL`/`KV_REST_API_TOKEN` 조합을 인식합니다. 연결이 없거나 응답하지 않으면 요청 제한 대상 작업을 허용하지 않습니다.

## 배포 차단 조건

- `AUTH_SECRET`이 32자 미만이면 프로덕션 런타임을 시작하지 않습니다.
- `ALLOW_DEMO_AUTH=true`가 아니면 빈 프로덕션 DB에 데모 계정을 만들지 않습니다.
- Vercel 운영 환경에 Neon 또는 Upstash 연결이 없으면 `/api/health`가 503을 반환합니다.
- 알림 웹훅 비밀이 없거나 서명이 다르면 요청을 거부합니다.
- GitHub Actions는 타입 검사, 테스트, 프로덕션 빌드와 번들 예산을 커밋 상태로 검사합니다.
- Vercel 프로젝트 루트는 `apps/web`이며, 배포 빌드는 저장소 루트의 `pnpm verify`를 호출합니다. 같은 검사 중 하나라도 실패하면 배포 산출물을 만들지 않습니다.
