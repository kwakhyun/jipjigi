# 프로덕션 준비 상태

## 현재 실행 가능한 범위

현재 저장소는 인증된 임대 운영 웹앱의 완결된 세로 단면을 제공합니다. 로그인한 사용자는 건물 브리핑을 보고, 계약 갱신 확인과 미납 안내를 접수하고, 수리 상태와 납부 상태를 변경할 수 있습니다. 각 변경은 SQLite에 저장되고 감사 로그와 제품 이벤트로 이어집니다.

구현된 운영 경계는 다음과 같습니다.

- 서명된 HTTP 전용 세션 쿠키와 요청별 사용자 재검증
- 건물 소유권을 포함한 모든 변경 대상 재조회
- 임차인 연락 동의, 7일 빈도 제한, 조용한 시간대 예약
- 멱등 키가 있는 CRM 요청과 HMAC 웹훅 검증
- 허용 목록 기반 제품 이벤트 속성 필터링
- 사용자 ID 기반 고정 A/B 배정과 실제 노출 기록 분리
- 지역 랜딩 정적 생성, 메타데이터, 구조화 데이터, 사이트맵
- 상태 확인 API, 구조화 로그, 독립 오류와 로딩 화면
- Core Web Vitals 수집, 최근 7일 p75 관제, CI 전송량 예산
- Upstash Redis sliding window와 장애 시 bounded 인메모리 폴백

## 외부 계약 전에는 켜지 않는 기능

아래 기능은 공급자 계약이나 운영 자격 증명이 없으므로 실제 연동이라고 주장하지 않습니다.

- 카카오 알림톡 실제 발송
- 은행 입금 내역 자동 수집
- 본인인증, 결제, 임대차 신고
- 광고 네트워크와 앱 푸시 공급자

현재 `sandbox_alimtalk` 어댑터가 동일한 메시지 상태 모델을 사용합니다. 실제 공급자는 어댑터를 교체하고 비밀 키를 주입한 뒤 계약 테스트를 통과해야 합니다.

## 수평 확장 전에 교체할 부분

로컬과 단일 인스턴스 데모는 WAL 모드 SQLite를 사용합니다. 다중 인스턴스 운영에서는 다음 작업이 선행되어야 합니다.

1. PostgreSQL과 버전 관리형 마이그레이션으로 데이터 계층을 교체합니다.
2. 제품 이벤트와 RUM을 내구성 큐로 보내고 웨어하우스 적재 실패를 재시도합니다.
3. 실제 인증 공급자, 사용자 초대, 비밀번호 재설정, MFA를 연결합니다.
4. Secrets Manager, 중앙 로그와 오류 추적을 운영 환경에 연결합니다.

Redis 요청 제한 코드는 구현되어 있습니다. 실제 수평 확장 환경에서는 Upstash 자격 증명 두 개를 주입하고 `/api/health`에서 `rateLimitStore: redis`를 확인해야 합니다.

## 배포 차단 조건

- `AUTH_SECRET`이 32자 미만이면 프로덕션 런타임을 시작하지 않습니다.
- `ALLOW_DEMO_AUTH=true`가 아니면 빈 프로덕션 DB에 데모 계정을 만들지 않습니다.
- 알림 웹훅 비밀이 없거나 서명이 다르면 요청을 거부합니다.
- 타입 검사, 단위 테스트, 프로덕션 빌드 중 하나라도 실패하면 CI가 배포를 막습니다.
