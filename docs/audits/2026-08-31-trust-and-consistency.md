# 이벤트 신뢰 경계와 기능·문서 정합성 개선

검증일: 2026-08-31 (KST)

이 기록은 앞선 계약 조회 오류와 데모 전환 개선에 이어 수행한 소스 검토, 로컬 회귀 검사와 브라우저 검증을 설명한다. 배포 성공은 이 파일을 포함한 커밋의 GitHub Actions와 Vercel 상태로 별도 확인한다. 이전 감사의 통과 판정은 그때의 버전과 검사 범위에만 해당한다.

## 수정한 핵심 발견 사항

| 문제 | 조치 | 검증 근거 |
| --- | --- | --- |
| P1: 공개 이벤트 API에 서버 전용 이벤트를 제출할 수 있었음 | 브라우저 이벤트 5개만 허용하고 익명은 SEO CTA만 허용. 납부 완료, CRM 전달 등은 내부 경로로 제한 | analytics server 및 API 테스트 |

| 수신 해제 지표가 전달 이전의 해제도 집계하고 계약을 사람으로 표시 | 같은 채널의 전달 이후 7일 이내 해제만 집계. 최근 7일 전달 계약 코호트의 잠정 비율로 명시 | 전달 전후, 다른 채널, 미래 시각을 분리한 PostgreSQL 테스트 |
| 실험 전환과 노출의 문맥이 불일치할 수 있었음 | 같은 실험과 실험안의 24시간 내 조치만 연결하고 복수 실험안 노출 사용자는 제외 | 조회 SQL 검토 및 PostgreSQL 실행 |
| 설정 저장 활동이 내부 영문 코드로 표시됨 | 한국어 활동 문구와 일반 변경 기록용 대체 문구 제공 | 저장 후 브리핑 조회 테스트 |

서버 전용 이벤트 차단은 브라우저 행동 자체가 진짜임을 보장하지는 않는다. 사용자 입력 기반 노출과 클릭은 여전히 비신뢰 신호이며, 서버 조치와 분리해 해석한다. 기존 저장 이벤트는 삭제하거나 재작성하지 않았으므로 수정 이전 수집분은 릴리스 버전을 구분해 분석해야 한다.

## 정합성을 맞춘 문서

- README와 아키텍처: 홈 조회의 TanStack Query, 선택 상태의 Jotai, 서버 props와 목록별 로컬 상태를 구분했다. 서버 변경 성공 시 업무 화면 경로를 재검증한다.
- PRD와 운영 문서: Neon 연결은 구현 상태로, 실제 CRM 공급자와 예약 자동 처리 워커는 미구현 상태로 정리했다. 예약 저장만으로 자동 발송이 완성됐다고 설명하지 않는다.
- 이벤트와 실험 문서: 필수 속성, 서버 문맥, 실제 전환 쿼리, 계약 단위 수신 해제 지표, 기본 발송 제한 21:00~08:00을 일치시켰다.
- 디자인 문서: 바텀시트 등 프로토타입 목표와 현재 웹 구현, 폰트 파일 제공 여부를 구분했다.
- SEO 문서: `generateStaticParams` 선언은 있으나 현재 빌드와 prerender manifest에서 공개 페이지 정적 HTML이 확인되지 않는다. 서버 렌더링 구현으로 표기하고 정적 산출 검증은 후속 최적화로 남겼다.
- 과거 QA 기록: 당시 테스트 수와 제약을 보존하고 이번 검증으로 연결했다. 과거 ‘P0/P1 없음’을 모든 후속 버전의 보증으로 사용하지 않는다.

## 검증 범위

`pnpm verify`로 웹 23개 파일의 77개 테스트, 공통 패키지 8개 테스트, 5개 패키지 타입 검사와 프로덕션 빌드, 10개 주요 경로의 번들 예산을 검사한다. 최신 번들 수치는 [성능 문서](../OBSERVABILITY.md)에 기록한다.

이번 실행은 모두 통과했다. README와 프로젝트 문서 18개의 상대 링크 67개가 실제 파일로 연결되는 것도 확인했다. 보호된 모바일 프로토타입은 무결성 검사 28개 파일과 정적 배포 테스트 4개가 통과했으며, 브라우저 런타임 테스트는 별도 CI 작업에서 검증한다.

CI와 같은 `VERCEL_ENV=production`을 주입한 웹 테스트도 77개 모두 통과했다. 테스트 설정이 운영용 외부 저장소 환경을 격리하는지 함께 확인한 것이다.

테스트는 실제 PostgreSQL 엔진인 PGlite를 메모리 모드로 격리한다. 디스크 영속성이 필요한 개발 환경은 파일 저장을 유지하고, Vercel Production의 Neon 필수 조건도 유지한다. 이전 전체 검사 시간 초과를 회피하려고 타임아웃을 완화하지 않았다. 테스트가 메모리 모드에서 통과한 사실만으로 이전 장치 부하가 원인이었다고 단정하지 않는다.

브라우저에서는 외부 DB와 Redis 연결을 비운 별도 임시 로컬 DB를 사용했다. 실제 공급자나 운영 데이터에 메시지를 보내지 않았다.

- 임대인 로그인, 홈과 계약의 갱신 미리보기 대상 선택 확인
- 계약 25건 조회와 메시지 센터 정상 렌더링
- 알림 3개를 끈 뒤 홈 카드만 숨겨지는 것을 확인하고 다시 켬
- 22:00~09:00 설정 저장 후 메시지 센터의 표시 일치 확인
- 임대인 → 그로스 → 임대인 로그인 전환, 일반 로그아웃 확인
- 모바일 390px에서 메시지 화면과 역할 전환 버튼 확인, 가로 넘침 없음
- 로컬 샌드박스 접수 버튼 실행. 외부 자동 발송은 검사 대상이 아님

## 남은 운영 경계

실제 인증, 외부 메시지 공급자, 내구성 큐와 예약 워커, 공급자 장애 중지 및 복구 처리, 실트래픽 기반 실험 성과 검증은 이번 수정의 완료 범위가 아니다. 비용이 발생하는 서비스나 요금제 변경 없이 기존 데모 구조를 보강했다. [프로덕션 준비 상태](../PRODUCTION-READINESS.md)의 운영 전환 항목을 별도로 충족해야 한다.
