# 프로젝트 검토 문제 개선 — 2026-09-05

[원본 검토](2026-09-05-project-review.md)의 10개 항목과 모바일 장부, 수리 일정 변경, 계약 검색의 추가 사용성 문제를 수정했다. 대상은 실제 Next.js 앱과 공통 패키지다. 보호된 프로토타입과 운영 데이터는 변경하지 않았다.

## 수정 내용

| 검토 항목 | 적용한 변경 | 회귀 검증 |
| --- | --- | --- |
| 1. 납부 완료 후 미납 안내 | 청구 상태를 트랜잭션 안에서 잠금 조회. 최초 접수와 재시도 모두 `overdue`만 허용하고 그 외 409 반환 | paid/upcoming 거부, 입금 뒤 실패 메시지 재접수 거부, 실제 API 409 |
| 2. 입금과 수리의 부분 저장 및 경합 | 대상 행 잠금, 현재 상태 검증, 업무 변경과 감사 로그 및 제품 이벤트를 동일 트랜잭션으로 저장 | 동시 입금 확인 3건 중 실제 변경 1건, 감사 저장 실패 시 전체 롤백, 완료 후 이전 상태 거부 |

| 6. 대비와 작은 글자 | 코럴과 초록의 텍스트 색 분리, 보라 버튼 대비 조정, 8~11px 운영 문구를 12px로 확대 | 실제 Chromium의 색 대비 검사와 확대 검증을 E2E에 추가 |
| 7. 발송함 상태 이해 | 접수, 예약, 전달 시각을 각각 표시. 차단 사유를 한국어 본문으로 안내하고 시간 설정 링크 제공 | 예약 datetime과 레이블, 수신 동의 차단 문구, 전달 시각 회귀 검사 |
| 8. 홈 조회 왕복 | 지표, 전체 건수와 대표 카드, 활동을 한 SQL 문장으로 집계 | 스냅샷 호출의 query 1회, 다른 소유자 접근 거부 |

추가로 모바일 장부 요약을 압축하고 ‘미납 N건 보기’에서 필터와 목록 이동을 함께 수행한다. 모바일 행에는 상태와 작업 버튼을 가로 스크롤 없이 배치했다. 수리는 저장한 방문 일정을 다시 편집할 수 있고, 계약 검색이 비면 설명과 초기화 버튼을 제공한다.

전달 및 수신 해제 웹훅, 갱신 응답, 알림 설정도 업무 결과와 기록을 같은 트랜잭션에서 저장한다. DB 저장 실패 웹훅은 잘못된 본문을 뜻하는 400 대신 재시도 가능한 500을 반환한다. 실패 메시지 재접수도 현재 동의와 최근 접수 횟수를 다시 확인한다.

## 구조와 운영 명령

- `apps/web/lib/data`: 업무 조회와 관측을 책임별 파일로 분리했다. `repository.ts`는 기존 호출을 위한 export 진입점이고, 클라이언트 공유 타입은 `types.ts`에 있다.
- 계약 타임라인은 PostgreSQL 행 번호로 계약별 최근 8건만 반환하고 Map으로 연결한다. 발송함의 수신자 검색도 Map을 사용한다.
- `packages/ui/src/styles.css`는 공통 색상과 글자 크기, 버튼과 배지 규칙을 제공한다. 화면 배치는 앱의 `globals.css`에 둔다.
- 새 로컬 환경은 `pnpm db:setup` 이후 `pnpm dev`로 시작한다. 기존 데이터는 유지된다. 삭제가 필요한 로컬 초기화만 `pnpm db:reset`을 사용한다.
- Vercel은 `pnpm verify` 뒤 `pnpm db:migrate`를 실행한다. Docker는 전체 저장소가 있는 배포 작업에서 마이그레이션을 먼저 실행한다. 실제 런타임은 DDL을 실행하지 않는다.

## 검증 기록

- 웹 단위 및 통합: 캐시 없는 직렬 실행에서 **33개 파일, 138개 테스트 통과**. 첫 실행의 2개 실패는 변경된 버튼 문구 및 현재 시각 검증과 테스트의 고정 날짜가 맞지 않아 발생했고, 테스트의 기대 문구와 시간을 명시한 뒤 다시 통과했다.
- 공통 패키지: **8개 테스트 통과**.
- 워크스페이스 타입 검사: **5개 패키지 통과**.
- Next.js 프로덕션 빌드와 **10개 경로의 기존 번들 예산 통과**. 홈 177.3/185KiB, 메시지 168.7/170KiB. 예산은 올리지 않았다.
- 최종 실제 웹앱 E2E **7개 모두 통과**(약 1.9분). 업무 저장과 격리, 모바일 조작, 검색과 일정 변경, 접근성 및 데스크톱 세션에서 200% CSS 확대 후 입금 확인을 검증했다. [최종 실행 로그](2026-09-05-remediation-evidence/e2e.log)를 보관했다.
- 실제 Chromium에서 홈, 장부, 계약, 수리, 메시지, 설정의 393px/1440px 접근성 검사 통과. `color-contrast`를 활성화해 12개 화면 조건을 검사했다. 최초 검사에서 드러난 보조 글자 대비 4.4~4.48:1도 토큰을 수정한 뒤 재검증했다.
- agent-browser로 393×850 장부를 열고 미납 필터를 직접 조작했다. 페이지 너비 393px, 오류 오버레이 0개, 브라우저 오류 없음. [첫 화면](2026-09-05-remediation-evidence/ledger-mobile.png), [미납 작업 화면](2026-09-05-remediation-evidence/ledger-overdue-mobile.png), [명령 출력과 검사값](2026-09-05-remediation-evidence/)을 보관했다.
- 전체 브라우저 실행의 확대 검사는 데스크톱 접근성 여정과 로그인 세션을 공유한다. 별도 로그인을 추가했을 때는 실제 10분 10회 로그인 제한에 걸렸으며, 서비스 제한을 낮추거나 테스트 인증 우회를 추가하지 않았다.

## 검증의 한계와 후속 조건

동시 호출과 롤백은 실제 PostgreSQL 엔진인 PGlite에서 검증했다. PGlite는 단일 연결이므로 Neon 다중 연결의 행 잠금 대기와 처리량 부하 시험을 대체하지 않는다. 홈 SQL 왕복 감소는 코드와 호출 횟수로 검증했으며 운영 LCP나 응답 시간이 특정 비율로 빨라졌다고 주장하지 않는다.

현재 데모는 계약 25건과 최근 메시지 50건으로 제한되어 있다. 목록 전체 캐시는 계약과 장부 및 메시지 대상 선택에서 공유한다. 실사용 데이터가 늘어날 때의 서버 검색과 커서 페이지네이션은 확장 조건이며 이번 데모에 새로 도입하지 않았다. 타임라인의 불필요한 전체 전송과 반복 필터링은 이번에 제거했다.

실제 메시지 공급자, 예약 자동 발송 워커, Neon 장애 주입과 운영 배포는 이번 작업 범위에 포함되지 않는다. 마이그레이션 실행 절차는 [런북](../RUNBOOK.md), 실제 브라우저 검증 범위는 [E2E 문서](../E2E.md)에 정리했다.
