# 계약 조회 오류와 데모 계정 전환 개선

검증일: 2026-08-31 (KST)

후속 상태: 당시 중단한 전체 회귀 검사는 이후 통과했다. 테스트용 PGlite를 메모리 저장소로 분리했고 검사 시간 제한은 유지했다. 아래 내용은 당시 기록이며 최종 범위는 [후속 개선 기록](2026-08-31-trust-and-consistency.md)을 기준으로 확인한다. 앞선 시간 초과의 원인이 장치 부하였다고 단정하지 않는다.

## 원인

운영 배포 `dpl_GS65jFGbUPAn7zyfDe6oDWyxCrhW`의 04:26 로그에서 `/app/contracts`, `/app/messages` 모두 PostgreSQL 오류 `42703: column "occurredat" does not exist`를 확인했다.

두 화면이 공통으로 호출하는 `listContracts()`는 발송 이벤트와 갱신 응답을 합친 후 `occurredAt`으로 정렬한다. SQL 어댑터는 SELECT 별칭을 `"occurredAt"`으로 변환하지만, 따옴표 없는 ORDER BY 이름은 PostgreSQL에서 소문자로 해석된다. 데이터가 없는 초기 상태에서도 쿼리가 실패했다. 명시적으로 인용한 정렬 컬럼으로 수정했다.

이 오류는 스트리밍 응답 시작 후 발생해 운영 로그에 HTTP 200으로 기록된 요청도 있었다. 상태 코드만으로 정상 여부를 판단하지 않고, 실제 조회 쿼리와 렌더링 결과를 함께 검증한다.

로그인 페이지의 기존 세션 리다이렉트도 문제였다. `mode`로 다른 데모를 요청해도 현재 계정의 홈으로 이동했으며, 로그아웃은 설정 화면에서만 제공되었다.

## 변경 내용

- 계약 조회 정렬 컬럼을 수정하고, 최신순 타임라인과 최대 8개 표시를 회귀 테스트로 보호했다.
- 데모를 활성화한 환경에서는 로그인 상태에서도 데모 선택 화면을 열 수 있다. 일반 서비스 모드의 기존 로그인 리다이렉트는 유지한다.
- 모든 업무 화면 상단에 현재 역할, 로그아웃, 반대쪽 데모 전환 버튼을 배치했다.
- 데모 전환은 현재 세션을 삭제한 뒤 선택한 데모의 로그인 화면을 연다. 역할을 클라이언트에서 직접 바꾸거나 자동으로 권한을 부여하지 않는다.
- 로그인 성공 후에는 DB에서 확인한 역할로 세션과 목적지를 결정한다. 계정 전환 시 업무 화면 캐시를 무효화하고 계정별 화면 상태를 다시 생성한다.
- 로그인 탭의 계정 정보, 설명, 제출 버튼과 목적지를 동기화했다. 외부 URL이나 해당 역할에 허용되지 않은 목적지는 역할별 홈으로 대체한다.

## 역할별 범위

| 화면의 명칭 | 실제 역할 | 확인할 수 있는 화면 |
| --- | --- | --- |
| 임대인 데모 | `owner` | 브리핑, 임대 장부, 계약 관리, 수리 요청, 메시지 센터, 설정 |
| 그로스 데모 | `operator` | 그로스 관제, 운영 설정 |

그로스 데모는 기존의 ‘운영자 데모’와 같은 계정이다. 명칭만 업무 목적에 맞게 바꿨으며, 개별 임대 계약에 대한 접근 권한은 확대하지 않았다.

## 재현 가능한 검증

- 수정 전 PGlite 통합 테스트 2개가 운영과 같은 `occurredat` 오류로 실패하는 것을 확인했다.
- 수정 후 초기 계약 25건, 빈 발송함, 발송 이벤트와 갱신 응답의 합산 및 정렬, 다른 계정의 데이터 차단을 검증했다.
- 로그인 목적지, 인증 실패 시 기존 세션 보존, 양방향 로그아웃 전환, 데모 비활성화, 기존 세션에서의 데모 선택을 테스트했다.
- 로컬 브라우저에서 임대인 로그인 → 계약 관리 → 메시지 센터 → 그로스 전환 및 로그인 → 임대인 전환 및 재로그인 → 일반 로그아웃을 완료했다.
- 로그아웃 후 계약 URL이 로그인으로 이동하고, 임대인 계정으로 그로스 URL을 열면 접근이 차단되는 것을 확인했다.
- 모바일 390px 화면에서 전환 버튼 표시와 가로 넘침이 없는 것을 확인했다.

검사 범위를 구분한다. 이번 변경에 직접 관련된 6개 파일의 30개 테스트와 전체 TypeScript 검사는 통과했다. 이후 전체 웹 테스트 실행에서는 동일 DB 조회 테스트가 30초 제한을 넘겼고, 실행 옵션만 60초로 늘린 단일 작업 재시도에서도 약 112초가 걸려 시간 초과했다. 해당 전체 검사는 중단했으며, 전체 테스트가 통과했다고 간주하지 않는다. 타임아웃 설정이나 검사 기준을 소스에서 완화하지 않았다.

전체 회귀 검사와 별도로 실행한 Next.js 프로덕션 빌드와 10개 경로의 번들 예산 검사는 통과했다. 운영 배포 전에는 장치 실행 환경을 안정화한 뒤 전체 회귀 검사를 다시 통과시켜야 한다.

```sh
pnpm typecheck
pnpm --filter @jipjigi/web test --maxWorkers=1
pnpm build
pnpm bundle:check
```
