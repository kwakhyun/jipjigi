# 실제 사용자 검증 계획

상태: **아직 모집하거나 실행하지 않은 계획**. 사용성 관찰 결과, A/B 전환율, 리텐션과 매출 개선 수치는 없습니다. 로컬 자동 테스트와 AI의 화면 검토는 실제 사용자를 대신하지 않습니다.

## 먼저 확인할 질문

“위험을 먼저 보여주는 홈에서 임대인이 다음 행동과 그 이유를 이해하고, 연락 접수 결과를 확인할 수 있는가?”를 확인합니다. 첫 관찰에서 두 디자인의 통계적 우열이나 사업 성과를 판단하지 않습니다.

## 작은 사용성 관찰

처음에는 임대 관리 경험자 또는 계약과 수리 연락 경험이 있는 유사 사용자 3~5명을 목표로 합니다. 모집 규모는 과제의 오해를 발견하기 위한 계획이며 대표성이나 통계적 유의성을 보장하지 않습니다. 참여자를 아직 확보하지 않았습니다. 유사 사용자라면 실제 임대인과 구분해 기록합니다.

참여 전에 목적, 약 20분의 예상 시간, 기록 범위, 중단 가능 여부와 결과 공유 범위를 설명하고 동의를 받습니다. 녹화는 별도 동의가 있을 때만 하며 실제 계약서, 연락처와 금액을 요청하지 않습니다. 데모의 가상 인물과 데이터만 사용합니다. 보상이나 외부 발송처럼 비용이 발생하는 진행은 별도 결정합니다.

### 관찰 과제

1. 처음 로그인한 화면에서 가장 먼저 처리할 일을 고르고 이유를 설명해 주세요.
2. 만료가 가까운 계약을 찾아 안내 내용을 확인하고, 데모 메시지를 접수해 주세요.
3. 새로고침 후 방금 접수한 메시지가 어떤 상태인지 설명해 주세요. 접수, 예약과 실제 전달을 구분하는지 관찰합니다.
4. 수리 요청의 방문 일정을 잡고 저장됐는지 확인해 주세요.

진행자는 위치를 미리 알려주지 않고 성공이나 실패를 유도하지 않습니다. 도움을 준 경우 시점과 내용을 기록합니다. 실제 외부 발송으로 오해하거나 기록 삭제에 불안감을 보이면 해당 작업을 멈추고 설명합니다.

### 기록할 항목

| 항목 | 기준 |
| --- | --- |
| 과제 완료 | 서버 저장 또는 정확한 상태 설명까지 스스로 도달했는지. 도움받은 완료는 따로 구분 |
| 최초 행동까지 시간 | 과제 설명을 마친 때부터 관련 첫 행동까지. 화면을 연 순간과 혼동하지 않음 |
| 재탐색과 오류 | 잘못 선택한 메뉴, 반복 시도, 오류 안내를 이해하지 못한 지점 |
| 상태 이해 | 샌드박스 접수, 발송 시간 예약과 전달 완료를 자신의 말로 구분하는지 |
| 발화와 관찰 | 직접 말한 내용과 관찰자의 해석을 다른 칸에 기록 |
| 접근성 문제 | 기기, 확대, 입력 방식과 방해받은 동작. 사용자를 진단하거나 능력을 추정하지 않음 |

참여자별 익명 ID, 날짜, 테스트한 커밋, 홈 구성과 기기 조건을 함께 남깁니다. 원본 녹화와 개인정보를 공개 저장소에 올리지 않으며 보존 기간과 삭제 요청 처리 방법은 동의 단계에서 정합니다.

## 개선 판단과 재검증

기능이 중단되거나 상태를 반대로 이해한 문제를 먼저 고칩니다. 여러 사람이 같은 곳에서 막혔다면 정보 구조나 문구를 검토합니다. 소수의 발언을 전체 사용자 요구로 일반화하지 않습니다.

수정 전 관찰, 원인 가설, 바꾼 부분, 다른 대안과 부작용을 기록합니다. 같은 과제로 다시 확인할 때는 학습 효과가 있음을 명시하고 가능한 경우 새 참여자에게도 확인합니다. “참여자 4명 중 3명이 도움 없이 완료했다”처럼 분모와 조건을 공개하며, 이를 전체 전환율이나 상대 개선율로 확대하지 않습니다.

## A/B 실험은 그다음 단계

개인 데모에서 직접 고른 홈 구성은 무작위 표본이 아니며 12시간 만료 공간은 D7 리텐션을 측정할 수 없습니다. 관제에 1명 노출과 1명 조치가 보이더라도 승리한 실험안이 아닙니다.

실제 A/B를 하려면 장기 사용자 식별과 데이터 보존, 분석 동의와 운영 조건을 먼저 마련해야 합니다. 내부 데모와 봇을 제외한 실제 기준선을 모은 뒤 [실험 설계](EXPERIMENTS.md)의 표본 크기, 관찰 창과 가드레일을 확정합니다. 사용자 관찰에서 드러난 오해를 수정한 뒤에도 비교할 질문이 남을 때만 실행합니다.

## 결과를 추가할 때 사용할 형식

아래는 작성 양식이며 실행 결과가 아닙니다.

```text
검증 날짜 / 커밋 / 환경:
질문과 변경 전 예상:
참여자 수와 관련 경험 / 모집 방법:
동의와 기록 범위:
과제별 무도움 완료 / 도움받은 완료 / 실패:
직접 관찰한 문제:
해석과 남은 불확실성:
선택한 개선 / 포기한 대안:
재검증 결과와 학습 효과:
다음 결정: 유지 / 반복 / 제거
```

이 기록을 채울 실제 참여자는 프로젝트 소유자가 모집해야 합니다. 참여 승인이나 실제 결과를 AI가 만들어 채우지 않습니다.
