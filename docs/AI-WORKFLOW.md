# AI 활용과 검증 원칙

## 1. 이 프로젝트에서 AI가 한 일

1. 공개 서비스와 임대관리 도메인을 빠르게 조사해 제품 문제를 구체화했습니다.
2. 정보 우선순위가 다른 모바일 홈 시안 세 가지를 생성했습니다.
3. 선택된 3번의 시각 방향에 1번의 수납 기능과 2번의 일정 기능을 합친 통합 시안을 만들었습니다.
4. 헤더 슬롯 크기에 맞는 야간 건물 전용 자산을 별도로 생성했습니다.
5. 선택 시안을 React 프로토타입으로 옮기고 상호작용, 이벤트, 문서를 작성했습니다.

## 2. AI에게 맡기지 않은 판단

- 제품의 핵심 사용자가 누구인지
- 어떤 행동을 북극성 지표에 포함할지
- CRM 발송의 동의와 야간 제한 기준
- 근거 없는 위험 확률을 사용하지 않는 원칙
- 실제 구현과 목표 아키텍처를 구분하는 표현
- 최종 화면의 정보 우선순위와 제거할 기능

## 3. 검증 게이트

AI 결과는 다음 순서를 통과해야 저장소의 기준이 됩니다.

```text
도메인 근거 확인
  → 시안 비교
  → 사용자 선택과 피드백
  → 독립 자산 제작
  → 타입 검사와 빌드
  → 실제 브라우저 상호작용
  → 기준 이미지와 시각 비교
  → 문서와 코드 용어 일치 확인
```

## 4. 안전 원칙

- 실제 임차인 정보, 연락처, 계좌, 계약서를 프롬프트에 넣지 않습니다.
- 공개 서비스는 문제와 정보 밀도 참고에만 사용하고 브랜드와 화면을 복제하지 않습니다.
- 생성된 성과 수치를 실제 사용자 결과처럼 표현하지 않습니다.
- 법률, 추심, 신용 판단을 AI가 자동 결정하지 않습니다.
- 발송 문구는 승인된 템플릿과 운영 가드레일을 통과해야 합니다.

## 5. 팀 생산성으로 확장

- PR 설명에서 AI가 만든 코드와 사람이 결정한 정책을 구분합니다.
- 이벤트 스키마, 접근성, 개인정보, 실험 제거를 코드 리뷰 체크리스트에 넣습니다.
- 반복되는 컴포넌트 생성은 디자인 토큰과 Storybook 기준을 먼저 제공합니다.
- AI가 제안한 라이브러리는 번들, 유지보수, 라이선스, 런타임 호환성을 검토한 뒤 채택합니다.
- 실패한 프롬프트와 수정 이유를 짧게 남겨 같은 오류를 반복하지 않습니다.
