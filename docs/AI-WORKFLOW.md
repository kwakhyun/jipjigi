# AI 활용과 검증 기록

이 프로젝트는 AI의 시각 탐색, 코드 생성, 테스트 작성과 문서 검토를 적극 활용했습니다. 모든 코드를 AI 없이 직접 작성했다거나, 작업 시간을 몇 배 줄였다고 주장하지 않습니다. 생산성 비교를 위한 시간 기록과 대조 작업은 없으므로 절감률도 제시하지 않습니다.

## 역할을 어떻게 나눴는가

프로젝트 소유자가 채용 포지션과 임대 관리 도메인, 완성도 목표를 정하고 결과물을 검토했습니다. 3번 디자인 방향에 다른 시안의 기능을 합치는 선택, 집지기 브랜드 결정, 화면 오류 제보와 개선 우선순위 요청도 소유자의 피드백입니다.

AI는 이를 바탕으로 기획안을 구체화하고 이미지, React와 Next.js 코드, 테스트, 문서를 작성했습니다. 코드 리뷰와 실행 검증에도 AI가 참여했습니다. 정책의 상세 수치나 구현 판단을 전부 사람이 독립적으로 결정했다고 표현하지 않습니다. 최종 제출 시에는 아래 코드와 선택 이유를 본인이 설명하고 변경할 수 있어야 합니다.

## 선택과 포기한 대안

- **화면마다 Query를 넣지 않았습니다.** 계약과 장부는 메시지 대상 선택과 같은 원본을 사용하므로 공유 캐시가 필요했습니다. 조회 전용 그로스 관제와 공개 페이지는 Server Component로 유지했습니다. 라이브러리 사용 개수가 아니라 중복 상태와 동기화 책임을 기준으로 판단했습니다.
- **데모를 매번 전역 초기화하지 않았습니다.** 첫 방문 화면은 같아지지만 다른 평가자의 작업이 사라집니다. 별도 계정과 공간을 만들고 본인 초기화에 한정했습니다. 저장량이 무제한 늘지 않도록 유효 시간과 저장 개수도 제한했습니다.
- **실험안 선택을 같은 사용자 ID의 토글로 구현하지 않았습니다.** 서로 다른 안의 노출과 행동이 섞일 수 있기 때문입니다. 새 공간으로 시작하게 하고 해당 결과를 실험 성과로 해석하지 않도록 표시했습니다.
- **입금과 발송을 낙관적으로 성공 처리하지 않았습니다.** 서버가 저장한 결과를 다시 읽습니다. 실패 시 자동 재실행도 하지 않습니다. 샌드박스 접수와 실제 전달은 다른 상태로 남깁니다.

## 검증에서 주의한 점

AI가 테스트를 작성한 사실과 테스트가 통과한 사실을 구분합니다. 실행하지 못한 검증은 성공으로 표시하지 않으며 기존 버전의 결과를 최신 변경의 근거로 재사용하지 않습니다. 프로토타입의 Playwright 통과를 실제 Next.js 웹앱의 E2E 통과로 표현하지 않습니다.

수정할 때는 문제를 재현하는 테스트, 타입 검사, 빌드, 번들 예산, 실제 화면 확인과 문서 대조 순으로 근거를 쌓습니다. 현재 실행 결과와 남은 검증은 [개선 사례](case-studies/demo-reproducibility.md)에 기록합니다. 자동 검사만으로 모든 기기와 보조 기술의 접근성을 보증하지 않습니다.

## 공개와 안전 기준

- 실제 임차인의 연락처, 계좌와 계약서를 AI 입력이나 테스트 데이터로 사용하지 않습니다.
- 경쟁 서비스는 문제 이해에 참고하되 브랜드와 화면은 독립적으로 만듭니다.
- 테스트 이벤트와 데모 RUM을 실제 고객 성과로 표시하지 않습니다.
- 실제 알림톡, 결제, 금융 연동과 유료 서비스 변경은 별도 권한 없이 수행하지 않습니다.
- 사용성 관찰, 동료 코드 리뷰, 매출 개선과 팀 생산성 변화는 실제 증거가 있을 때만 경력 사례로 추가합니다.
