# 전달 계획과 Definition of Done

- 갱신 확인, 미납 안내, 수리 요청
- 홈 정보 순서 실험
- 로컬 이벤트 기록

### 단계 1: 프로덕션 기반

부분 완료입니다. 구현과 후속 범위를 구분합니다.

- 완료: pnpm, Turborepo와 Next.js App Router 구성
- 완료: 공통 TypeScript와 Vitest 설정
- 완료: 서명 세션, 역할 분리, 상태 확인 API와 환경 변수 검증
- 완료: GitHub Actions 품질 검사와 Vercel 공개 배포
- 후속: React Native 앱, Panda CSS primitives, ESLint와 Storybook

### 단계 2: 임대 운영 MVP

샌드박스 웹 MVP로 구현했습니다. 실제 발송과 예약 처리 워커는 이 완료 범위에 포함되지 않습니다. 최신 검증과 공개 배포 상태는 커밋별로 구분합니다.

- 건물, 호실, 계약, 청구 데이터 모델
- 홈 브리핑 Server Component
- 갱신 확인 Server Action과 모바일 API
- 서버 생성 멱등 키, 갱신 24시간 제한과 청구월 단위 미납 안내
- 수리 요청 상태 전이
- 서버 보장 이벤트 수집과 제품 내 그로스 관제
- 전달 상태 웹훅, 실패 재접수와 계약 단위 응답 타임라인
- 브라우저별 개인 데모, 한국 날짜 기준 시나리오, 자신의 기록만 초기화하는 체험 설정

### 단계 3: 성장 실험

핵심 실험은 구현했고, 가입 활성화와 실제 결과 리드아웃은 후속입니다.

- 위험 우선안과 일정 우선안
- 완료: 실험안별 노출과 조치 사용자 집계

- 후속: 가입 활성화 체크리스트와 CRM 문구 변형
- 후속: 실제 트래픽 결과 리드아웃 자동 생성

### 단계 4: 유입과 수익화

SEO 유입 기반은 구현했고 수익화는 별도 검증 뒤 진행합니다.

- 완료: 지역별 임대관리 SEO 랜딩과 전환 CTA

## 3. 기능 Definition of Done

기능은 다음 조건을 모두 만족해야 완료입니다.

1. 사용자 문제와 핵심 지표가 PRD에 연결돼 있습니다.
2. 기본, 로딩, 빈 상태, 오류, 성공, 재시도 상태가 있습니다.
3. 키보드와 스크린리더로 핵심 흐름을 끝낼 수 있습니다.
4. 이벤트 이름, 속성, 중복 방지 기준이 리뷰됐습니다.
5. 개인 정보가 로그와 분석 속성에 들어가지 않습니다.
6. 핵심 경로 단위 테스트와 브라우저 시나리오가 통과합니다.
7. 성능 예산을 넘지 않습니다.
8. 롤백 또는 실험 제거 방법이 있습니다.
9. 스테이징에서 디자인 비교와 콘솔 오류 검사가 끝났습니다.
10. 배포 뒤 확인할 지표와 담당자가 정해져 있습니다.

## 5. 배포와 롤백

현재 저장소의 개인 데모는 새 임대인 ID를 기준으로 기본 실험안을 해시 배정합니다. 체험 설정에서 안을 선택하면 새 작업공간으로 시작하며, 그 결과는 무작위 실험 표본이 아닙니다. GitHub Actions에 실제 웹앱 E2E를 추가했으며 타입, 테스트, 빌드와 번들 예산도 검사합니다. Vercel은 별도로 `pnpm verify`를 실행합니다. CI 성공과 배포 SHA의 일치를 확인한 뒤 공개 버전의 완료로 판단합니다.

실제 트래픽 운영에서는 다음 정책을 추가합니다.

- 실험 기능은 기본 비활성 상태로 배포합니다.
- 내부 계정, 1%, 10%, 50%, 100% 순으로 확장합니다.
- 오류율, 발송 실패율, 수신 해제율이 한도를 넘으면 자동 또는 수동으로 기본안으로 되돌립니다.
- 데이터 스키마 변경은 이전 버전과 호환되는 두 단계 배포를 사용합니다.
- UI 롤백과 메시지 발송 중단을 별도 스위치로 운영합니다.

## 6. 포트폴리오 전달 체크리스트

- 디자인 기준 이미지가 저장소에 있습니다.
- 프로토타입 실행과 검증 명령이 README에 있습니다.
- PRD, 실험, 이벤트, 아키텍처가 서로 같은 용어를 사용합니다.
- 실제 구현과 목표 설계를 명확히 구분합니다.
- 모의 성과를 실제 수치처럼 제시하지 않습니다.
- 실패하거나 미구현인 항목과 다음 계획을 숨기지 않습니다.
- 개인 데모에서 두 역할과 두 홈 구성을 재현하고 다른 방문자의 데이터가 섞이지 않는지 확인합니다.
- 실제 웹앱 E2E와 보호된 프로토타입 테스트의 결과를 따로 기록합니다.
- AI 활용, 실제 사용성 관찰과 가상 시나리오 검증을 구분합니다.
