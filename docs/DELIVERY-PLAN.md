# 전달 계획과 Definition of Done

## 1. 단계별 출시

### 단계 0: 시각 및 상호작용 검증

현재 완료된 범위입니다.

- 통합 디자인 기준 고정
- iPhone과 Pixel 런타임
- 갱신 확인, 미납 안내, 수리 요청
- 홈 정보 순서 실험
- 로컬 이벤트 기록

### 단계 1: 프로덕션 기반

예상 1주입니다.

- pnpm과 TurboRepo 초기화
- Next.js App Router와 React Native 앱 생성
- 공통 TypeScript, ESLint, 테스트 설정
- Panda CSS 의미 토큰과 핵심 primitives
- 인증 스텁, 상태 확인 API, 환경 변수 검증
- GitHub Actions와 preview 환경

### 단계 2: 임대 운영 MVP

예상 2주입니다.

- 건물, 호실, 계약, 청구 데이터 모델
- 홈 브리핑 Server Component
- 갱신 확인 Server Action과 모바일 API
- 미납 안내 멱등 처리
- 수리 요청 상태 전이
- 이벤트 수집과 스테이징 대시보드

### 단계 3: 성장 실험

예상 1주입니다.

- 서버 배정과 노출 이벤트
- 위험 우선안과 일정 우선안
- 가입 활성화 체크리스트
- CRM 문구 실험과 수신 해제 가드레일
- 실험 결과 템플릿 자동 생성

### 단계 4: 유입과 수익화

별도 검증 뒤 진행합니다.

- 지역별 임대관리 SEO 랜딩
- 공실 등록 전환 흐름
- 수리 비교 견적 문맥형 제휴 지면
- 광고 SDK 샌드박스와 빈도 제한

## 3. 기능 Definition of Done

기능은 다음 조건을 모두 만족해야 완료입니다.

1. 사용자 문제와 핵심 지표가 PRD에 연결돼 있습니다.
2. 기본, 로딩, 빈 상태, 오류, 성공, 재시도 상태가 있습니다.
3. 키보드와 스크린리더로 핵심 흐름을 끝낼 수 있습니다.
4. 이벤트 이름, 속성, 중복 방지 기준이 리뷰됐습니다.
5. 개인 정보가 로그와 분석 속성에 들어가지 않습니다.
6. 핵심 경로 단위 테스트와 브라우저 시나리오가 통과합니다.
7. 성능 예산을 넘지 않습니다.
8. 롤백 또는 실험 제거 방법이 있습니다.
9. 스테이징에서 디자인 비교와 콘솔 오류 검사가 끝났습니다.
10. 배포 뒤 확인할 지표와 담당자가 정해져 있습니다.

## 4. 테스트 전략

| 층 | 대상 | 예시 |
|---|---|---|
| 단위 | 도메인 규칙 | 위험 우선순위, 야간 제한, 멱등 키 |
| 컴포넌트 | UI 상태 | 갱신 시트 로딩, 성공, 실패, 포커스 |
| 계약 | API와 이벤트 | 모바일 API 스키마, 이벤트 버전 |
| 통합 | 데이터 흐름 | Server Action 뒤 Query 캐시 갱신 |
| 브라우저 | 핵심 여정 | 홈에서 갱신 요청 완료, 미납 안내 완료 |
| 시각 | 기준 시안 | 393px, 427px 화면 비교 |
| 접근성 | 핵심 화면 | 이름, 역할, 대비, 키보드 순서 |
| 성능 | 주요 route | 번들, LCP, INP, 이미지 예산 |

## 5. 배포와 롤백

- 실험 기능은 기본 비활성 상태로 배포합니다.
- 내부 계정, 1%, 10%, 50%, 100% 순으로 확장합니다.
- 오류율, 발송 실패율, 수신 해제율이 한도를 넘으면 자동 또는 수동으로 기본안으로 되돌립니다.
- 데이터 스키마 변경은 이전 버전과 호환되는 두 단계 배포를 사용합니다.
- UI 롤백과 메시지 발송 중단을 별도 스위치로 운영합니다.

## 6. 포트폴리오 전달 체크리스트

- 디자인 기준 이미지가 저장소에 있습니다.
- 프로토타입 실행과 검증 명령이 README에 있습니다.
- PRD, 실험, 이벤트, 아키텍처가 서로 같은 용어를 사용합니다.
- 실제 구현과 목표 설계를 명확히 구분합니다.
- 모의 성과를 실제 수치처럼 제시하지 않습니다.
- 실패하거나 미구현인 항목과 다음 계획을 숨기지 않습니다.
