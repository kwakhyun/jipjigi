# 기능 구현 현황

제품 기능과 기술 구성의 구현 범위, 검증 근거와 후속 작업을 정리합니다. 데모에서 확인한 동작과 실제 운영에서 검증해야 할 항목을 구분합니다.

## 제품 기능

| 항목 | 현재 구현 | 범위와 근거 |
| --- | --- | --- |
| 관리 브리핑 | 계약 만료, 미납, 수리 일정과 입금 확인을 한 화면에 연결 | 서버 저장까지 구현 |
| 개인 데모 | 브라우저별 작업공간, 상대 날짜, 본인 초기화와 역할 전환 | [재현성 검증](case-studies/demo-reproducibility.md) |
| 홈 구성 실험 | 위험 우선안과 일정 우선안을 사용자별로 고정 배정하고 실제 렌더 뒤 노출 기록 | 배정과 수집 구현, 실제 트래픽 실험 결과 없음 |
| 행동 로그와 관제 | 타입 이벤트, 영속 저장, 퍼널과 가드레일 집계 | [이벤트 계약](EVENTS.md), [실험 설계](EXPERIMENTS.md) |
| 메시지 접수 | 미리보기, 동의, 목적별 중복 제한, 멱등 키, 전달과 응답 웹훅, 실패 재접수 | 샌드박스 구현. 실제 채널과 예약 처리 워커 미연동 |
| 지역 가이드 | 서버 렌더링, 메타데이터, JSON-LD, robots, sitemap과 전환 CTA | 구현, 검색 유입 성과는 미측정 |
| 문맥형 광고 | 수리 비교 견적 지면, 빈도 제한과 이탈 가드레일 정의 | 후속 설계, 광고 SDK 미연동 |

## 기술 구성과 검증

| 항목 | 현재 구현 | 범위와 근거 |
| --- | --- | --- |

| 상태 관리 | 서버 조회는 SSR hydration과 계정별 Query, 선택 건물은 Jotai, 필터와 입력 초안은 로컬 상태 | [판단과 테스트](QUERY-STATE.md) |
| 데이터 저장 | 운영 Neon Postgres, 로컬 PGlite, 변경 작업의 트랜잭션과 행 잠금 | [수정 기록](audits/2026-09-05-remediation.md) |
| 공통 패키지 | analytics, experiments, domain, ui를 workspace 패키지로 분리 | 도메인 API와 공통 UI 제공 |
| 디자인과 접근성 | CSS 의미 변수, 공통 UI, 시맨틱 요소와 포커스 스타일 | 6개 화면에서 두 너비의 색 대비와 200% CSS 확대 검사 |
| 성능 | 서버 초기 조회, 경로별 번들 예산, Core Web Vitals 수집과 최근 7일 p75 관제 | 번들 예산 검사 통과, 실제 트래픽 표본 필요 |
| 자동 검증 | 타입 검사, 단위 및 통합 테스트, 프로덕션 빌드와 웹앱 E2E | 날짜별 결과는 [변경 기록](VERSION-HISTORY.md), 실행 방법은 [E2E 문서](E2E.md) |
| 배포 | GitHub Actions 검사와 Vercel 배포 | CI 성공과 실제 배포 SHA는 별도 확인 필요 |
| AI 활용 | 시안, 코드와 테스트 작성 및 리뷰에 AI 활용 | [작업 기록](AI-WORKFLOW.md). 시간 절감률은 미측정 |

## 후속 작업

- 동의받은 임대인 또는 유사 경험자를 대상으로 핵심 과제를 관찰하고 개선 전후를 확인합니다. [사용성 관찰 계획](USER-VALIDATION.md)은 아직 수행 결과가 아닙니다.
- 실제 운영에 필요한 인증, 메시지 공급자와 예약 워커, 오류 추적 및 운영 경보를 보강합니다. 세부 경계는 [프로덕션 준비 상태](PRODUCTION-READINESS.md)에서 확인합니다.
- 실제 트래픽이 확보되면 정의한 표본 조건과 가드레일에 따라 실험을 판단합니다. 현재 수집 구조만으로 전환율이나 매출 개선을 주장하지 않습니다.
- 공통 UI의 공개 API와 접근성 검증을 확장합니다. Panda CSS와 React Native는 목표 구조이며 현재 구현에는 포함되지 않습니다. 앱 내 웹의 실기기 연동도 추가 검증이 필요합니다.
