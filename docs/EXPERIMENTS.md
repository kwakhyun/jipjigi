# 실험 설계

## 1. 운영 원칙

- 실험은 디자인 변경이 아니라 사용자 행동과 사업 결과를 검증하는 단위로 정의합니다.
- 실험 노출, 핵심 행동, 가드레일을 출시 전에 함께 설계합니다.
- 통계적 유의성만으로 결정하지 않고 효과 크기, 사용자 불편, 운영 비용을 함께 봅니다.
- 실험 종료 뒤 승자 코드만 남기고 배정 로직, 임시 이벤트, 전용 스타일을 제거합니다.
- 실패 결과도 가설, 관찰, 다음 질문 형태로 기록합니다.

## 2. 지표 사전

| 이름 | 계산식 | 관찰 창 | 제외 조건 |
|---|---|---|---|
| 브리핑 행동 시작률 | 추천 행동 시작 사용자 / 브리핑 노출 사용자 | 노출 후 24시간 | 내부 계정, 봇, 중복 노출 |
| 브리핑 행동 완료율 | 추천 행동 완료 사용자 / 브리핑 노출 사용자 | 노출 후 24시간 | 권한 오류 사용자 |
| 위험 해결 시간 | 위험 노출부터 상태 완료까지의 시간 | 최대 14일 | 이미 해결된 위험 |
| 7일 재방문율 | 첫 행동 후 6~8일에 유효 행동한 사용자 / 첫 행동 사용자 | 8일 | 탈퇴 계정 |
| CRM 수신 해제율 | 전달 후 같은 채널에서 수신 해제한 계약 / 메시지 전달 계약 | 전달 후 7일 | 전달 전 해제, 다른 채널, 미래 시각 |
| 중복 발송률 | 동일 멱등 키로 두 번 이상 수신 / 전체 수신 | 당일 | 테스트 번호 |

모든 지표는 사용자 단위와 메시지 단위를 분리합니다. 클릭률이 높아도 수신 해제율이나 불만율이 함께 오르면 성공으로 보지 않습니다.

현재 관제는 브리핑 노출 후 24시간 내 조치율, 전달률, 차단률과 계약 단위 수신 해제율을 계산합니다. 수신 해제율은 최근 7일 전달 계약의 진행 중 관찰을 포함하는 잠정치입니다. 나머지 지표, 실제 사용자 대상 제외 정책과 통계적 판단은 실험 설계이며 자동 구현된 결과가 아닙니다.

## 3. 실험 A: 홈 브리핑 우선순위

### 질문

임대인은 위험 한 건을 먼저 볼 때 행동을 더 빨리 끝낼까요, 아니면 오늘 일정을 먼저 볼 때 더 많이 참여할까요?

### 가설

위험을 먼저 보여주면 추천 행동의 이유가 분명해져 24시간 내 행동 완료율이 높아집니다. 반대로 일정 우선안은 화면 탐색과 여러 업무 확인에는 유리할 수 있습니다.

### 변형

| 변형 | 설명 |
|---|---|
| risk-first | 계약 만료 위험, 근거, 주 CTA를 먼저 노출한 뒤 오늘 일정을 보여줌 |
| agenda-first | 오늘 일정을 먼저 노출하고 위험 카드와 CTA를 다음에 보여줌 |

### 대상과 배정

- 대상: 활성 계약이 있고 이번 주 처리 항목이 한 건 이상인 임대인
- 배정 단위: 사용자 ID
- 비율: 50:50
- 고정 기간: 실험 전체 기간
- 제외: 회사 내부 계정, 최근 24시간 안에 같은 위험을 이미 해결한 사용자

### 이벤트

```text
experiment_exposed
  → risk_evidence_opened
  → renewal_started
  → crm_message_delivery_updated
```

### 판단

- 1차 지표: 브리핑 행동 완료율
- 2차 지표: 근거 열람률, 행동 시작까지 걸린 시간, 홈 체류 시간
- 가드레일: 이탈률, 잘못된 위험 신고율, 홈 오류율, LCP
- 최소 표본: 실제 2주 기준선을 수집한 뒤 양측 검정, 유의수준 5%, 검정력 80%, 최소 감지 효과 8~10% 상대 개선으로 계산
- 종료: 사전 계산 표본 도달과 최소 2개의 완전한 주기를 모두 만족

### 구현 상태

프로덕션 웹앱은 로그인 사용자 ID를 기준으로 서버에서 실험안을 고정 배정하고 Neon Postgres에 저장합니다. UI가 실제로 렌더된 뒤에만 `experiment_exposed`를 세션당 한 번 기록하며, 그로스 관제에서 실험안별 노출 사용자와 조치 사용자를 확인할 수 있습니다. 보호된 프로토타입은 시각 비교를 위해 같은 두 정보 순서를 로컬 저장소로 전환합니다.

## 4. 실험 B: CRM 미납 안내 문구

### 질문

정중하고 구체적인 안내가 짧고 직접적인 안내보다 수납 확인을 높이면서 수신 해제를 줄일 수 있을까요?

### 변형

| 변형 | 핵심 문구 |
|---|---|
| concise | 납부 확인이 필요하다는 사실과 확인 경로만 안내 |
| considerate | 이미 납부했다면 무시해도 된다는 문장과 문의 경로 포함 |

### 대상 제한

- 지연 3일 이상이며 이번 달 안내를 받지 않은 계약
- 마케팅 수신이 아니라 계약상 운영 알림에 동의한 사용자
- 기본 발송 제한 시간은 한국 시간 21:00~08:00이며 저장된 임대인 설정을 적용합니다. 메시지 미리보기에도 현재 설정을 표시합니다.
- 미납 안내는 같은 계약과 청구월에 1회만 발송
- 갱신 확인은 같은 계약에 24시간 동안 1회, 최근 7일 동안 최대 2회 발송

### 지표

- 1차: 발송 후 72시간 내 수납 확인율
- 2차: 메시지 상세 열람률, 임대인 후속 행동률
- 가드레일: 수신 해제율, 신고율, 고객센터 문의율, 중복 발송률

가드레일이 사전 한도를 넘으면 성과와 관계없이 실험을 중단합니다.

## 5. 실험 C: 가입 직후 활성화

### 질문

빈 홈을 보여주는 대신 첫 건물 등록을 3단계 체크리스트로 안내하면 첫 관리 행동까지 더 많은 사용자가 도달할까요?

### 퍼널

```text
가입 완료
  → 건물 등록
  → 호실과 계약 1건 등록
  → 첫 청구 일정 생성
  → 첫 브리핑 행동 완료
```

- 1차: 가입 24시간 내 활성화율
- 2차: 단계별 완료율과 중단 시간
- 가드레일: 평균 등록 시간, 도움말 진입률, 등록 오류율

## 6. 신규 그로스 기능 후보

### 운영 날씨 알림

비, 한파, 폭염을 단순 정보로 보내지 않고 누수 점검, 동파 예방, 공용부 확인 같은 관리 행동과 연결합니다. 지역과 건물 유형이 없는 사용자는 대상에서 제외합니다.

### 계약 캘린더 브리핑

매일 열게 만드는 목적보다 30일 안의 계약과 수리 일정을 놓치지 않게 하는 목적을 우선합니다. 무의미한 출석 보상은 사용하지 않습니다.

## 7. SEO 실험

- 대상 페이지: 지역별 임대관리 체크리스트와 공실 등록 안내
- 변형: 계산 결과를 먼저 보여주는 랜딩과 설명을 먼저 보여주는 랜딩
- 1차: 유효 건물 등록 전환율
- 2차: 검색 클릭률, CTA 도달률
- 가드레일: 짧은 체류 후 이탈, 잘못된 기대를 만든 문의 비율

검색 순위 자체를 실험 성공 지표로 단독 사용하지 않습니다. 유입 뒤 실제 제품 가치에 도달했는지 확인합니다.

## 8. 광고 수익화 실험

MVP 뒤 수리 업체 비교 견적 문맥에서만 제휴 지면을 검토합니다.

- 빈도 제한: 사용자당 7일 2회
- 제외: 긴급 수리 중, 발송 실패 상태, 신규 활성화 이전 사용자
- 핵심: 유효 견적 요청과 eCPM
- 가드레일: 관리 행동 완료율, 앱 종료율, 광고 숨김률, 7일 재방문율
- SDK는 어댑터 뒤에 두고 공급자 교체와 완전 제거가 가능해야 합니다.

## 10. 실험 제거 체크리스트

1. 기본 변형을 제품 코드에 직접 반영합니다.
2. 서버 배정 키를 비활성화하고 프로토타입의 로컬 배정 값을 만료합니다.
3. 변형 전용 컴포넌트, 스타일, 테스트를 제거합니다.
4. 실험 전용 이벤트 속성을 더 이상 보내지 않습니다.
5. 대시보드를 읽기 전용 결과로 보관합니다.
6. 제거 PR에 실험 결론과 후속 위험을 연결합니다.
