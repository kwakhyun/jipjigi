# 렌트플로우 PRD

문서 버전: 1.0
기준일: 2026-08-29
상태: 시각 프로토타입과 프로덕션 웹 MVP 구현 완료, 외부 공급자 연동 전

## 1. 제품 한 문장

여러 임대 업무를 한꺼번에 보여주는 장부가 아니라, 임대인이 오늘 놓치면 비용이 생길 일 한 가지를 먼저 발견하고 끝낼 수 있게 하는 운영 브리핑입니다.

## 2. 해결할 문제

소규모 임대인은 전담 관리 인력이 없습니다. 입금 내역, 계약 만료, 수리 요청, 임차인 연락이 서로 다른 채널에 흩어져 있어 문제가 생긴 뒤 대응하기 쉽습니다. 기존 장부형 화면은 기록에는 유용하지만, 지금 무엇을 해야 하는지 결정하는 비용을 충분히 줄여주지 못합니다.

렌트플로우는 세 가지 문제를 우선 해결합니다.

1. 계약 만료나 미납처럼 비용으로 이어질 가능성이 큰 일을 제때 발견하기 어렵습니다.
2. 임차인에게 연락할 때 문구, 채널, 발송 시각, 수신 동의를 함께 확인하기 어렵습니다.
3. 앱을 다시 열 이유가 월말 장부 확인에 치우쳐 일상적인 관리 루프가 약합니다.

## 3. 목표 사용자

### 핵심 사용자

- 주택, 오피스텔, 상가 1~20개 호실을 직접 관리하는 임대인
- 전담 관리 직원이 없고 카카오톡, 계좌 내역, 달력으로 업무를 나눠 처리하는 사람
- 디지털 도구에는 익숙하지만 복잡한 자산관리 시스템은 원하지 않는 사람

### 초기 제외 사용자

- 수백 개 호실을 관리하며 회계, 시설, 권한 체계가 필요한 전문 PM 회사
- 매매 투자 분석이 주목적인 사용자
- 임차인용 집 찾기와 계약 중개만 필요한 사용자

## 4. 사용자가 끝내야 하는 일

> 오늘 내 임대 운영에서 가장 중요한 일을 확인하고, 근거를 이해한 뒤, 적절한 채널로 후속 조치를 완료한다.

보조 작업은 다음과 같습니다.

- 월별 수납 상태를 호실 단위로 확인한다.
- 수리 요청을 읽고 권장 대응 시간 안에 업체 배정을 요청한다.
- 계약 만료 전 갱신 의사를 확인한다.
- 미납 안내가 과도하게 발송되지 않았는지 확인한다.
- 필요한 알림만 받도록 채널과 수신 설정을 관리한다.

## 5. 제품 원칙

1. 위험을 과장하지 않습니다. 확인 가능한 날짜와 기록을 근거로 보여주며 근거 없는 확률을 만들지 않습니다.
2. 한 화면에는 주 행동 하나를 둡니다. 나머지는 일정과 요약으로 접어 판단 부담을 줄입니다.
3. CRM 성과보다 사용자의 통제권을 먼저 둡니다. 수신 동의, 수신 해제, 야간 제한을 발송 조건에 포함합니다.
4. 실험 전에는 최소 단위로 만들고, 효과가 확인된 흐름만 완성도를 높입니다.
5. 실패한 실험은 코드와 문서에서 제거할 수 있어야 합니다.

## 6. 성공 지표

### 북극성 지표

주간 유효 관리 임대인 수: 7일 안에 브리핑을 보고 갱신 확인, 미납 안내, 수리 처리, 수납 확인 중 하나를 완료한 고유 임대인 수입니다.

### 핵심 지표

| 지표 | 정의 | 초기 목표 |
|---|---|---:|
| 활성화율 | 가입 24시간 안에 건물과 계약을 등록하고 첫 관리 행동을 완료한 비율 | 기준선 대비 15% 개선 |
| 브리핑 행동 완료율 | 브리핑 노출 후 24시간 안에 추천 행동을 완료한 비율 | 기준선 대비 10% 개선 |
| 7일 재방문율 | 첫 유효 관리 행동 후 7일째 전후 1일 안에 다시 유효 행동을 한 비율 | 기준선 대비 8% 개선 |
| 위험 해결 시간 | 위험 노출부터 후속 조치 완료까지 걸린 중앙값 | 기준선 대비 20% 단축 |

### 가드레일

- 알림톡과 푸시 수신 해제율
- 발송 실패율과 중복 발송률
- 고객센터 불만 접수율
- 잘못된 위험 판정 신고율
- 홈 LCP, INP, 오류율

초기 목표는 실제 기준선 수집 뒤 다시 고정합니다. 포트폴리오 단계에서 임의의 성과 수치를 만들지 않습니다.

## 7. MVP 범위

### 7.1 오늘의 관리 브리핑

- 현재 건물을 바꿀 수 있습니다.
- 계약 만료, 미납, 긴급 수리 가운데 우선순위가 가장 높은 한 건을 펼쳐 보여줍니다.
- 남은 안정 호실 수를 함께 보여 불필요한 불안을 줄입니다.
- 판단 근거를 별도 바텀시트에서 확인할 수 있습니다.

완료 조건:

- 위험 카드가 노출될 때 실험안과 위험 종류가 로그에 남습니다.
- 사용자는 홈에서 두 번 이하의 탭으로 후속 조치를 시작할 수 있습니다.
- 근거가 없는 위험에는 행동 CTA를 노출하지 않습니다.

### 7.2 계약 갱신 확인

- 계약 종료일과 현재 월세를 보여줍니다.
- 임차인에게 보낼 문구를 발송 전에 보여줍니다.
- 발송 채널의 수신 동의와 야간 제한을 확인합니다.
- 완료 후 홈 상태가 `요청 보냄`으로 바뀝니다.

완료 조건:

- 같은 계약에는 24시간 안에 중복 요청을 보내지 않습니다.
- 성공, 실패, 재시도 상태가 구분됩니다.
- 임차인의 응답은 계약 단위 타임라인에 기록됩니다.

### 7.3 미납 안내

- 지연 일수, 금액, 이번 달 발송 횟수를 확인합니다.
- 위협적인 표현을 피한 기본 문구를 제공합니다.
- 이미 납부한 경우 무시할 수 있다는 문구를 포함합니다.
- 수신 해제 사용자와 야간 시간대는 즉시 발송에서 제외합니다.

완료 조건:

- 사용자, 계약, 청구월 조합으로 멱등 키를 만듭니다.
- 발송 요청과 실제 채널 수신 결과를 별도 이벤트로 기록합니다.
- 수신 해제율은 실험 가드레일 대시보드에 포함합니다.

### 7.4 수리 요청

- 임차인 메모와 접수 시각을 보여줍니다.
- 누수 같은 긴급 유형에는 권장 대응 시간을 표시합니다.
- 업체 배정 요청 후 상태가 즉시 바뀝니다.

### 7.5 임대장부와 소식

- 월별 수납 금액과 호실별 상태를 확인합니다.
- 계약, 수리, 수납 관련 운영 알림을 한곳에서 확인합니다.
- 알림 설정은 필수 운영 알림과 선택형 마케팅 알림을 분리합니다.

### 7.6 실험과 이벤트

- 사용자 단위로 `risk-first`, `agenda-first` 중 하나를 고정 배정합니다.
- 실험 노출은 실제 UI가 렌더된 뒤 한 번만 기록합니다.
- 추천 행동 완료 이벤트에는 실험 ID와 변형을 함께 저장합니다.
- 종료된 실험은 기본안을 확정한 뒤 분기 코드를 제거합니다.

## 8. 핵심 사용자 흐름

```text
푸시 또는 직접 실행
  → 오늘의 브리핑 노출
  → 위험 근거 확인
  → 갱신 요청 또는 미납 안내 검토
  → 채널과 가드레일 확인
  → 발송 완료
  → 홈 상태 갱신
  → 임차인 응답 알림
```

## 9. 데이터 모델 초안

| 엔터티 | 핵심 필드 |
|---|---|
| Landlord | id, locale, timezone, notificationPreferences |
| Building | id, ownerId, name, addressMasked, unitCount |
| Unit | id, buildingId, label, occupancyStatus |
| Lease | id, unitId, startsAt, endsAt, monthlyRent, renewalStatus |
| Charge | id, leaseId, billingMonth, amount, dueAt, paidAt, status |
| MaintenanceRequest | id, unitId, category, severity, receivedAt, status |
| RiskSignal | id, entityType, entityId, reasonCode, evidence, expiresAt |
| MessageDispatch | id, templateId, channel, consentSnapshot, status, idempotencyKey |
| ExperimentAssignment | experimentId, subjectId, variant, assignedAt |
| ProductEvent | eventId, actorId, eventName, properties, occurredAt |

주소와 연락처 원문은 이벤트 로그에 넣지 않습니다. 분석에는 내부 식별자와 범주형 값만 사용합니다.

## 10. 비기능 요구사항

### 접근성

- 모든 행동 요소는 44px 이상의 터치 영역을 가집니다.
- 아이콘 버튼에는 읽을 수 있는 이름을 제공합니다.
- 상태 변화는 `aria-live`로 전달합니다.
- 색상만으로 상태를 구분하지 않습니다.
- 키보드 포커스가 명확히 보입니다.

### 성능

- 모바일 홈 LCP 2.5초 이하, INP 200ms 이하를 목표로 합니다.
- 홈 초기 JavaScript gzip 예산은 170KB 이하입니다.
- 헤더 이미지는 100KB 안팎으로 제공하고 화면 크기에 맞는 포맷을 사용합니다.
- 제품 데이터는 서버 렌더링 초기값을 전달하고, 클라이언트 재요청 폭포를 피합니다.

### 신뢰성과 보안

- 발송 API는 멱등 키를 필수로 받습니다.
- 채널 웹훅은 서명 검증 후 상태를 갱신합니다.
- 사용자 입력과 외부 채널 응답은 런타임 스키마로 검증합니다.
- 서버 로그에서 개인정보를 마스킹합니다.
- 감사 로그는 발송 문구 버전과 동의 스냅샷을 남깁니다.

### 관측 가능성

- 화면 오류, API 오류, 채널 발송 실패를 서로 다른 오류 코드로 수집합니다.
- 실험 대시보드는 핵심 지표와 가드레일을 같은 화면에서 봅니다.
- 릴리스 버전, 실험안, 사용자 세그먼트를 이벤트 공통 필드로 저장합니다.

## 11. MVP 이후

1. 가입 직후 건물 등록을 돕는 단계형 온보딩과 이탈 복구
2. 임대 운영 날씨 알림처럼 실제 관리 행동과 연결되는 재방문 기능
3. 공실 등록 SEO 랜딩과 지역별 임대관리 가이드
4. 수리 업체 비교 견적과 문맥형 제휴 지면
5. 광고 SDK 샌드박스 연동, 빈도 제한, eCPM과 이탈 가드레일 실험
6. React Native 앱에서 동일한 도메인 로직과 이벤트 스키마 공유

## 12. 범위 밖

- 실제 계좌 조회와 자동 입금 매칭
- 법률 자문, 강제 추심, 신용 평가
- 임차인 연락처의 실제 전송
- 결제, 광고 네트워크, 알림톡 운영 계정의 실제 연동

이 기능들은 별도 보안 검토, 파트너 계약, 개인정보 영향 평가가 필요합니다.
