# React 및 Next.js 코드 리뷰

검토일: 2026-08-29

## 적용한 개선

- 루트 레이아웃의 TanStack Query, Jotai 공급자를 대시보드 경계로 이동해 공개 페이지와 비대시보드 화면이 해당 런타임을 받지 않도록 분리했습니다.
- 통화 포맷 함수를 `@rentflow/domain/format` 서브패스로 분리해 클라이언트가 Zod 기반 서버 스키마를 함께 번들링하지 않게 했습니다.
- 웹 내부 변경은 인증과 런타임 스키마 검증을 포함한 Server Action으로 전환했습니다. 모바일과 외부 연동을 위한 Route Handler는 유지했습니다.
- 반복되는 수동 로딩 상태를 React 19 `useTransition`으로 바꾸고, 토스트 타이머는 공통 훅에서 중복 취소와 언마운트 정리를 수행합니다.
- 계약과 수리 화면의 상대 날짜 기준을 서버 ISO 문자열로 전달해 SSR과 hydration 시각이 달라질 가능성을 제거했습니다.
- 정의되지 않은 지역 랜딩은 성수동 콘텐츠로 폴백하지 않고 HTTP 404를 반환합니다.
- 유효하지 않은 세션 쿠키가 로그인과 앱 사이에서 반복 리다이렉트되지 않도록 로그인 페이지에서 서명을 검증합니다.
- 로그인 시도 제한과 사용자 존재 여부에 따른 bcrypt 시간 차이 완화, 공개 경로의 정확한 세그먼트 매칭을 적용했습니다.
- 프로덕션 모드에서도 SQLite 연결을 프로세스 단위로 재사용해 요청마다 연결이 누적되는 문제를 수정했습니다.
- 루트 레이아웃 오류를 처리하는 `global-error.tsx`를 추가했습니다.

Next.js `route-bundle-stats.json`의 초기 비압축 JavaScript 기준입니다.

| 경로 | 변경 전 | 변경 후 | 감소율 |

현재 빌드 청크를 개별 gzip으로 합산한 참고값은 `/app` 약 175KB, `/` 약 154KB입니다. 제품 홈의 170KB 목표에는 근접했지만 공개 랜딩의 90KB 목표는 넘습니다. 이 수치는 실제 CDN 전송 측정이 아니라 빌드 청크 합산이므로 운영 RUM과 함께 다시 기준을 잡아야 합니다.

## 검증 결과

- TypeScript: 5개 패키지 통과
- 단위 테스트: 10개 통과
- Next.js 16 프로덕션 빌드 통과
- 브라우저에서 대시보드 조치와 설정 저장 Server Action 확인
- 정의되지 않은 지역 URL의 HTTP 404 확인
- 유효하지 않은 세션 쿠키로 `/login` 접근 시 200, 리다이렉트 0회 확인

## 남은 과제

- 2026년 8월 30일에 경로별 gzip 예산과 Core Web Vitals RUM을 추가했습니다. 공개 경로 170KiB, 일반 앱 170KiB, `/app` 185KiB 예산이 CI에서 검사됩니다.
- Testing Library와 axe-core 기반 컴포넌트 접근성 검사를 Vitest와 CI에 연결했습니다.
- Upstash Redis sliding window를 추가했습니다. 자격 증명이 없는 로컬 환경은 bounded 메모리 저장소를 사용하며, `/api/health`에서 현재 모드를 확인할 수 있습니다.
- 다중 인스턴스의 영속 데이터 계층은 여전히 PostgreSQL 전환이 필요합니다. Redis 운영 활성화에는 실제 Upstash 자격 증명 주입이 필요합니다.
